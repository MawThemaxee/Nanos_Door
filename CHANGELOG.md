# Changelog

All notable changes to the `door` package are documented here.
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project
follows [Semantic Versioning](https://semver.org/).

## [0.2.1] - 2026-09-25

### Changed (breaking)

- **The repository root is now the package.** `Package.toml`, `Client/`, `Server/` and `Shared/`
  moved out of `packages/door/`, so you can clone the repo straight into your server as
  `Packages/door` and update it with `git pull`. If you had symlinked `packages/door`, point the
  link at the repository root instead.
- The interact key now always uses the game's built-in **`Interact`** binding. The custom
  "Open / close a door" binding (`DoorInteract`) and the constants `INTERACT_GLOBAL_BINDINGS`,
  `INTERACT_DEFAULT_KEY` were removed; `DoorEvents.INTERACT_BINDING` is now `"Interact"`.
- The `door-test` example package is no longer part of this repository.

### Removed

- Release archives (`door_v*.zip`) from the repository. Releases will be published as GitHub
  Releases instead.

### Fixed

- Log messages no longer wrap their arguments in `string.format`, since `Console.Warn` formats
  them itself.

## [0.2.0] - 2026-09-24

### Added

- **Interaction modes.** A door's mode decides what opens and closes it:
  - `trigger`: opens when a character walks in, closes when they walk out (default).
  - `interact`: the player looks at the door and presses the interact key.
  - `manual`: nothing automatic, only your own code opens or closes the door.
- `BaseDoor.RegisterInteractionMode(name, mode)` lets any package add its own mode (keycard,
  code, button, timer…) with the callbacks `OnInteract`, `OnBeginOverlap`, `OnEndOverlap`,
  `OnAttach` and `OnDetach`.
- Lock-aware helpers `door:TryOpen()`, `door:TryClose()`, `door:TryToggle()`, plus
  `door:Toggle()`, `door:IsOpen()`, `door:SetInteractionMode()` and `door:GetInteractionMode()`.
- Access to the trigger zone: `door:GetTrigger()` and `door:SetTriggerExtent(radius)`.
- **Map placement from Unreal Engine.** `BaseDoor.SpawnFromList(specs)` spawns doors from the
  `MapDoors.lua` file generated by the `nanos-door` Unreal plugin (separate repository), and
  `BaseDoor.RegisterMapType(name, builder)` lets new door types be placed the same way.
- Example `timed` mode: the door closes itself 3 seconds after being opened.

### Changed

- `HingeDoor` swings and `SlidingDoor` slides relative to the rotation it was spawned with, so
  doors placed at any orientation open the right way. `slide_offset` is now in the door's local
  space.
- `CharacterSimple` actors now trigger doors, not only `Character`.
- Compatibility version raised to nanos world `1.156`.

### Fixed

- `HingeDoor` and `SlidingDoor` never ran the shared `BaseDoor` constructor, so doors had no
  trigger and never opened when walked into.
- `DoorEvents.STATE_CHANGED` and `DoorEvents.LOCK_CHANGED` broadcasts were sent without their
  reliability argument, so clients never received the new state.

## [0.1.1] - 2026-09-24

### Added

- The door trigger also detects `CharacterSimple` actors.

## [0.1.0] - 2026-09-24

### Added

- First release: `HingeDoor` and `SlidingDoor`, built on a shared `BaseDoor` class.
- Custom mesh, scale and material per door (`SetDoorAsset`, `SetDoorScale`, `SetDoorMaterial`).
- Automatic opening with a trigger zone, and locking with `Lock()` / `Unlock()`.
- `DoorEvents.STATE_CHANGED` and `DoorEvents.LOCK_CHANGED` events.
